# Hold Monsters World · HoMoW

Самостоятельный репозиторий HoMoW, выделенный из [Brukivka](https://github.com/reformoti/Brukivka) версии 6.33.8 (коммит `fc4035594164af3544a98cff1ae7a6009ed9cf57`). Сохранены исходники клиента и сервера, игровые механики, оформление, десять музыкальных треков, шрифты и существующие ключи сохранений. Предыдущая история изменений находится в CHANGELOG.md и исходном репозитории.

**Онлайн-игра:** https://homow.92-5-85-199.sslip.io/

- GitHub хранит исходники. После одноразового включения таймера VPS автоматически получает проверенные обновления main; без установки таймера публикация коммита сама по себе не обновляет сервер.
- Oracle VPS запускает Node.js / WebSocket и отдаёт игру через Nginx / HTTPS.
- Существующая база Neon хранит аккаунты, сессии, персонажей и рейтинги. Перенос репозитория не создаёт новую базу и не сбрасывает прогресс.
- `index.html` и `realms.html` — исходный клиент. При раздаче обычной статикой это автономный режим с локальным сохранением. Для общего онлайн-мира нужен сервер из `homow-server/`.
- `homow.html` — собранная автономная HTML-версия. Шрифты и код встроены; музыка загружается отдельно. Этот файл генерируется, править следует исходные модули.

## Разработка и проверки

Нужны Node.js 22+ и Python 3 для сборки автономного HTML.

```sh
npm ci
npm test
npm run build
python3 scripts/build-homow.py
npm run build:transfer
```

`npm test` проверяет игровую логику, UI исходной и автономной версий, HTTP / WebSocket, команды владельца, сохранения, PvP, группы, музыку, кадровый ограничитель и сглаживание. Тесты используют изолированную БД в памяти; настоящий Neon при них не изменяется. `npm run test:db` отдельно проверяет подключённую PostgreSQL транзакцией с откатом.

Для локального сервера скопировать `.env.example` в `.env`, указать собственную строку подключения и `PUBLIC_ORIGIN`, затем выполнить `npm start`. Не публиковать `.env`, ключи, пароли или данные игроков.

## Обновление действующего VPS

На VPS рабочий каталог нового репозитория: `/var/www/homow`. Файл `deploy/vps/.env` остаётся приватным и использует прежнюю Neon. Compose сохраняет имя проекта `homow`, порт 3000 и прежний публичный адрес.

```sh
cd /var/www/homow
git pull --ff-only
sudo bash deploy/vps/install-auto-update.sh
sudo journalctl -u homow-auto-update.service -n 40 --no-pager
```

Сервер сохраняет персонажей при штатной остановке; во время обновления возможно краткое переподключение. После установки таймер проверяет main примерно каждые три минуты: успешные тесты, сборка, проверка запуска и откат при ошибке. Установка выполняется на VPS один раз; SSH-ключ не передаётся в GitHub. Ручное обновление и отключение таймера описаны в deploy/vps/README.md. Старый checkout `/var/www/brukivka` оставлен для отката; запускать оба одновременно на одном порту нельзя.

Подробности: [VPS](deploy/vps/README.md), [диагностика и кеширование](deploy/HOMOW-PERFORMANCE.md), [Nginx](deploy/nginx/homow.conf.example). Название на sslip.io связано с текущим IP VM; при смене IP требуется обновление адреса и сертификата.

## Совместимость

Кнопка возврата в Steam ведёт в существующую Brukivka. Её автономная копия HoMoW остаётся в исходном репозитории для совместимости. Дальнейшая разработка онлайн-игры и её развёртывание выполняются отсюда. Учётные данные Neon и SSH в репозиторий не входят.

Сценарии ручной проверки: [docs/6.34.0-PLAYTEST.md](docs/6.34.0-PLAYTEST.md).

XaR Cloud: https://xar-cloud.reformoti1.chatgpt.site/ . В профиле игры отдельно доступны вход/регистрация, создание полной копии и восстановление. Онлайн-копию подписывает сервер HoMoW; изменить её содержимое или восстановить под чужим HoMoW-логином нельзя. Автосохранение сервера работает независимо от ручной копии XaR Cloud. Для клиентов с других доменов требуется явно добавить доверенный origin в портал XaR Cloud. Пароли и серверные подписи не переносятся в локальный режим.

Локальное обновление не означает развёртывание на VPS. Рынок пока использует NPC-котировки, без ордеров между игроками.
